# App Insights（仅 App 维度）调研摘要

目标：为 FocusOrb 的付费版增加一个“截图里一眼看懂”的核心卖点：**我把专注时间花在哪些 App 上？我最常在哪些 App 里进入休息/中断？**

## 竞品/替代方案概览（桌面调研）

这类需求在市场上通常由“自动时间追踪/效率分析”工具满足（往往是订阅制、功能重、权限更敏感）：

- **Timing（macOS）**：自动追踪 App 使用时间、项目/标签、报表与导出；为拿到更细粒度信息（如文档/窗口标题）通常需要更高权限（如辅助功能）。  
  - https://timingapp.com/
- **RescueTime**：追踪应用与网站、生产力评分、Focus Session、阻断分心网站等（更偏“效率教练”）。  
  - https://www.rescuetime.com/
- **Rize**：自动时间追踪 + 专注/休息建议（更偏“行为洞察”）。  
  - https://rize.io/

## 机会点（FocusOrb 的差异化）

- **极简交互 + 可解释洞察**：竞品通常从“自动追踪”出发，复杂且重；FocusOrb 已经有“极简两态 + 事件流”，天然适合做“少而准”的洞察卡片（不做繁琐项目管理）。
- **权限与隐私叙事**：只做 **App 维度**（bundle id / app 名称 / 图标）即可形成强卖点，同时避免 URL/窗口标题带来的权限、兼容与用户信任成本。
- **与现有数据模型匹配**：FocusOrb 已有 `OrbEvent.meta`，可以以“低侵入”方式记录上下文，不必上来就引入复杂数据库 schema 迁移。

## 建议做的轻量用户调研（1 天内可完成）

目标：验证“App 维度洞察”是否足够有用，以及用户对隐私/权限的阈值。

建议样本（5–8 人即可）：
- 3–4 个时间感知困难/ADHD 或自认为“容易切换/分心”的用户
- 2–4 个知识工作者（开发/设计/运营/产品）

访谈问题（15 分钟）：
- 你现在怎么知道“今天主要干了什么”？哪里最不满意？
- 你最希望 FocusOrb 告诉你什么？（Top3）
- 如果给你一个榜单：“专注主要发生在 X/Y/Z App”，你会怎么用它做决策？
- 你能接受记录到什么粒度？（App 名 / 窗口标题 / 网址）
- 你最担心什么隐私风险？（工作聊天/银行/私密内容）
- 哪个呈现方式最能打动你付费？（Top Apps/分心排行/周报卡片/提醒）

## 建议定位（付费版主卖点文案草案）

- 你把专注时间花在哪些 App 上？
- 哪些 App 最容易让你从专注切到休息？
- 只记录应用名，**本地存储**，可随时关闭/清空。

## 风险与边界（务必在 PRD 中写清）

- 仅记录“切换瞬间的前台 App”会偏粗：如果用户在一个状态下频繁切 App，但不点击切换，归因会缺失。  
  解决策略：V1 先做“切换瞬间归因”，V1.5 再加“低频采样”可选项（并提供隐私说明与开关）。
